## What it changes and why it is safe

- **Adds 20 empty tables** (reports, cases, findings and their history). No existing table is rewritten.
- **Replaces one CHECK** on `staff_recovery_objections` so a staff objection must carry a 10–1000 character reason. The old CHECK let a missing reason through (a NULL comparison passes a CHECK). The application always required a reason, so existing rows should pass. If any row does not, the whole script rolls back (rehearsed); Step 1 shows it in advance.
- Runtime grants match the repository runner: read and write on the working tables; **SELECT and INSERT only** on the ten history tables, which also reject UPDATE and DELETE by trigger.
- Runs as `blacklist_migrator` with the same temporary-SET handling as earlier runbooks. Atomic: any error changes nothing.

**Rehearsal (2026-10-16, disposable PostgreSQL 18):** 12 entries applied by the repository runner from `main` (`3558cc2`), an existing recovery case and a valid staff objection seeded, then the script run as an owner role with ADMIN but no SET on the migrator (as on Neon).
